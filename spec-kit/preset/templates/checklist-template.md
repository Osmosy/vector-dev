# Чек-лист приёмки: [FEATURE NAME]

Приёмка — это перезапуск проверки, а не чтение отчёта. Чек-лист заполняет человек, но каждый
пункт подтверждается выводом команды.

## 1. Документы

- [ ] `check_spec.py --root . --json` вернул код 0
- [ ] у каждого требования REQ есть источник с адресом, sha256 и датой
- [ ] у каждого требования есть проверка, которую можно провалить
- [ ] каждое требование из spec.md есть в plan.md и хотя бы в одной задаче tasks.md
- [ ] в spec.md не осталось строк в «Открытые вопросы» без решения

## 2. Код

- [ ] `check_stage.py --stage <N>` вернул 0
- [ ] каждое требование этапа имеет адрес в коде (файл и функция)
- [ ] каждое требование этапа имеет запись в логе или доказательстве
- [ ] замороженные тесты и чекеры не изменены: дифф манифеста пуст

## 3. Коды выхода (не путать)

| Код | Что значит | Что делаем |
|---|---|---|
| 0 | принято | следующий этап |
| 1 | блокирующие находки | правим работу |
| 2 | плохой вход | правим документы/окружение |
| 3 | проверка сломана (подменён чекер) | разбираемся с проверкой, работу не трогаем |

## 4. Документация

- [ ] шаги инструкции пройдены на чистом окружении
- [ ] версии в инструкции совпадают с фактическими
- [ ] в инструкции нет шагов «как-нибудь» и ссылок на несуществующие файлы

## 5. Журнал

- [ ] в `acceptance/log.jsonl` запись: дата, этап, код выхода, версия чекера, что проверяли
- [ ] расхождения с прошлой приёмкой объяснены (что изменилось в проверке или в работе)

## 6. Что не проверено

Список того, что приёмка не покрывает. Заполняется всегда — пустой список означает, что его не
заполняли.
