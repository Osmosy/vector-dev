# Чек-лист этапов — <проект>

Копируется в корень проекта как `RAMKA.md` (раздел «этапы») или в `acceptance/checklist.md`.
Каждый пункт — бинарный: либо отмечен, либо блокирует переход.

## Г1 — GENERAL (до первой строки кода)

- [ ] стек и версии зафиксированы
- [ ] инструменты агента перечислены; отдельно — что запрещено
- [ ] карта данных: тестовое / обезличенное / вне зоны
- [ ] KPI как требование на 100 % (область, база, запрет самоотчёта)
- [ ] критерий «этап доведён» записан
- [ ] окружение изолировано: отдельная ВМ или контейнер, тестовые креды
- [ ] креды с минимальными правами; админская роль не выдаётся без письменной причины

## Г2 — RESEARCH (сырьё)

- [ ] дока нужной версии локально: md для агента, html для человека
- [ ] копия деплоя и все доступные логи в проекте
- [ ] бэкап БД развёрнут локально (контейнер)
- [ ] `research/INDEX.json`: у каждого источника `sha256`, версия, дата
- [ ] у каждого вывода — адрес: файл/строка, запрос, запись лога
- [ ] синтетика сгенерирована агентом через UI/API, а не взята из дампа

## Г3 — ARCHITECTURE (реестр и контракты)

- [ ] реестр требований: код, формулировка, источник, статус
- [ ] запись неизменяема; правка — новая ревизия с ребром `supersedes`
- [ ] спека сгенерирована из реестра и помечена как производная
- [ ] контракты между этапами лежат на диске
- [ ] список этапов с границами; каждое требование привязано к этапу
- [ ] гейт дрейфа запускается и даёт код выхода

## Г4 — STAGES (каждый этап)

- [ ] окно этапа: вход — реестр этапа + контракты + адреса (не история чата)
- [ ] чекер этапа: код выхода 0
- [ ] журнал приёмок: запись с кодом и временем
- [ ] замороженный набор тестов: дифф пуст
- [ ] каждое требование этапа имеет адрес в коде
- [ ] каждое требование этапа имеет запись в логе или доказательстве
- [ ] человек принял решение по красному/зелёному, а не искал ошибки руками

## Г5 — DOCS

- [ ] инструкция пользователя и администратора
- [ ] шаги пройдены на чистом окружении
- [ ] версии и стек в инструкции совпадают с фактическими
- [ ] перечислено, что не покрыто и где границы

## Коды выхода приёмки

| код | значение | решение |
|---|---|---|
| 0 | принято | идём дальше |
| 1 | блокирующие находки | доводим этап |
| 2 | плохой вход (нет рамки/источника) | возвращаемся к Г1/Г2 |
| 3 | отказ запускать (подменён чекер/набор тестов) | разбираемся с проверкой, не с кодом |
